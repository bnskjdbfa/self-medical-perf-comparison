# 세션 중복 저장·짧은 잠금 대기 후보 — 2026-10-21

추가 컴퓨트/인스턴스 없이 적용할 코드 후보를 로컬에서 검증했다. 운영·스테이징 DB/설정/배포는 변경하지 않았고 커밋·푸시도 하지 않았다.
기준은 별도 비교 저장소의 4756458113560100292fe4ec70dc8fdb6a376cc3이다. 후보는 아직 로컬 수정본이다.

## 확인한 문제와 수정

- 최종 설문 POST가 검증 전에 한 문항짜리 draft를 세션에 넣었다. 동시 INSERT의 IntegrityError 경로는 draft를 지우지 않아 불필요한 세션 저장·family 잠금을 일으켰다. 최종 제출에서는 이 draft를 만들지 않고, 중복 INSERT 경로도 기존 draft를 정리한다. DOM/question.id 기반 최종 payload 검증은 유지한다.
- 로드한 scoped generation에서 상태가 같은 명시적 save는 DB 작업을 생략한다. 신규 세션·legacy 채택·키 교체·flush·증가·만료 설정 변경은 생략하지 않는다. 명시적 save의 중첩 dict 수정은 modified 플래그 없이도 보존한다.
- 같은 세대의 일반 저장만 family 잠금을 기존 lock_timeout 내에서 기다린다. 기본 한도 200ms와 트랜잭션 wall/statement 예산 1500ms를 유지한다. 다른 잠금과 회전·폐기·채택은 NOWAIT를 유지한다. 요청 전체나 외부 I/O에 잠금을 걸지 않는다.
- 잠금 획득 후 세대·세션 만료를 다시 확인하고 three-way merge한다. 다른 요청이 같은 변경을 이미 저장했다면 session/family UPDATE와 만료 갱신을 생략한다. 이전 키로 새 인증을 조회하거나 복원하지 않는다.

일반 잠금 대기는 503을 줄일 수 있는 후보이지 모든 중복 요청을 성공시키는 보장이 아니다. 같은 필드의 서로 다른 변경은 계속 충돌하며, 본인확인의 Participant NOWAIT 잠금도 변경하지 않았다.
모델/migration·관리자 서비스·프론트·URL·필수동의·법정대리인·접근 제한은 변경하지 않았다.

## 검증

- 독립 localhost PostgreSQL 17.6, max_connections 30, Gunicorn 23.0.0 2×8/keep-alive 0.
- 최종 전체 프로젝트 회귀 422개 통과: 기존 413개 + 새 9개. 새 테스트는 no-op 저장, nested edit, 동일 변경 병합, 이전 세대 거절, 최종 draft, 짧은 경합 성공, timeout 쿠키/기존 상태 불변과 복구, 키 교체 NOWAIT를 검증한다.
- PostgreSQL에서 기존 관리자 테스트 2개의 테스트 가정을 보정했다. 문서 권한 집합 검사는 미지정 정렬을 요구하지 않으며, 조회 쿼리 수 검사는 고정된 lock_timeout 설정 SQL만 제외하고 기존 10회 한도를 유지한다. 관리자 서비스는 그대로다. 보정 전 실패 결과는 /tmp/duplicate-write-full-surveys-20261021.log 및 /tmp/duplicate-write-full-project-final-20261021.log에 보존했다.
- 도구 Python 테스트 21개 및 Node 부하 도구 guard/개인정보 회귀 통과.
- 초기 gthread 회귀: 쿠키 순서 7개, 동시 증가 60회, DB 오류·연결 고갈·statement timeout에서 쿠키 불변과 복구, 느린 뷰의 요청 전역 잠금 없음, 남은 워커 transaction 0. 느린 네트워크·클릭/Enter 연타·재시도·pageshow 브라우저 회귀 통과.
- 최종 소스 HTTP 재검증: 코드/본인확인 각 80회, 동시 증가 60회, 실제 워커별 8스레드 확인. 사용자 42명당 3중복 후 42명 인증 유지, 문서 126건·잠긴 설문 42건. 설문 제출 126회 모두 302. 본인확인 503 44건/409 84건, 문서 최종 503 7건/409 40건을 숨기지 않는다. 이 로컬 도구는 재시도를 사용하며 실제 스테이징 도구의 42 HTTP 상한과 동일한 부하 형태가 아니다.
